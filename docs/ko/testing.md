# 에뮬레이터와 피처폰 테스트

테스트 결과는 `헤더 -> 컴파일 -> 링크 -> 패키지 -> 로드 -> 엔트리 -> 첫
화면 -> 상호작용 -> 사용 가능 -> 완전 구현 -> 실기기 검증` 단계 중 어디까지
확인했는지 기록합니다. 뒤 단계 하나를 보았다고 중간 단계 전체나 다른 기기를
자동으로 지원한다고 판단하지 않습니다.

## 에뮬레이터 개발자

[다운로드 페이지](../generated/downloads.md)의 Release 번들은 하나의 정확한
API/ABI/설치 조합을 대상으로 합니다. 번들에는 실행 패키지만이 아니라 원본 C
소스, 리소스, 테스트 매니페스트, 예상 관찰값, 리비전 근거, SHA-256 목록이
함께 들어갑니다. 이 자료를 이용하면 공급자 구현에서 다음 항목을 재현할 수
있습니다.

- Clet 등록과 시작, 일시정지, 재개, 종료 생명주기
- 프레임버퍼와 그래픽 호출, 키 누름/뗌 이벤트
- 64비트 타이머 인자와 콜백
- 메모리 ID와 리소스 전달
- 해당 설치 프로필에 명시된 저장소, 네트워크, 미디어 범위

ARAM과 WIE의 공통 번들과 ARAM 전용 확장 번들은 서로 다른 계약입니다.
ARAM 전용 FS/DB/MDA 번호를 WIE나 실제 LGT 기기의 ABI 근거로 사용하면 안
됩니다.

Release 태그를 선택한 뒤 GitHub CLI로 번들과 외부 해시 목록을 받을 수
있습니다.

```powershell
$tag = "vX.Y.Z"
gh release download $tag --repo mirusu400/libwipi `
  --pattern "libwipi-*.zip" --pattern "SHA256SUMS"
Get-Content SHA256SUMS
Get-FileHash -Algorithm SHA256 .\libwipi-*.zip
```

ZIP을 푼 뒤에는 내부 `SHA256SUMS`도 확인하고 `bundle-manifest.json`의 API
레벨, ABI 프로필, 설치 프로필, 소스 리비전이 테스트 대상과 정확히 맞는지
먼저 확인하십시오.

## 피처폰 개발자와 기기 연구자

현재 Release 자산은 서명된 상용 설치 패키지나 보편적인 휴대전화 패키지가
아닙니다. 기기 검증을 추가할 때는 최소한 다음을 함께 기록하십시오.

1. 통신사, 제조사, 모델명, 정확한 펌웨어
2. 설치에 사용한 경로와 도구
3. API 레벨, ABI 프로필, 컨테이너 프로필
4. 테스트 패키지의 SHA-256
5. 도달한 가장 강한 단계와 실패한 API/동작

펌웨어나 상용 앱 바이트, 독점 SDK 바이너리, 서명 키는 저장소나 공개 테스트
번들에 넣지 않습니다. 확인되지 않은 ABI 값은 `candidate` 또는 `unknown`으로
남기고 별도의 검증 필요 조건을 기록합니다.

전체 명령과 게이트는 [영문 테스트 문서](../testing.md)를 참고하십시오.
