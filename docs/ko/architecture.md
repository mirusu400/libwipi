# 세 축으로 이해하는 libwipi

libwipi의 호환성은 한 줄짜리 “WIPI 지원” 표시가 아니라 다음 세 선택의
조합입니다.

```text
선택한 WIPI-C 소스 API 레벨
        -> 통신사/OEM/기기 ABI 어댑터
        -> 실행 파일 컨테이너와 설치 프로필
```

WIPI 규격은 공개 API와 동작을 정의하지만 모든 휴대전화가 공유하는 단일
네이티브 실행 파일 형식을 정의하지는 않습니다. 따라서 WIPI 2.x 기기라는
사실만으로 Samsung/KTF 테이블 ABI나 LGT/Raptor 번호 임포트를 선택하면 안
됩니다.

## 현재 프로필의 의미

- `ktf-samsung`은 복원된 Samsung/KTF 테이블 ABI의 근거 앵커입니다. 타깃
  라이브러리와 오브젝트 코드 검사는 있지만 휴대전화용 설치 프로필은 아직
  없습니다.
- `lgt-raptor`는 번호 임포트와 `binary.mod` ELF 컨테이너를 사용하는 ABI
  프로필입니다. `aram-wie-raptor`와 `aram-raptor`는 이 ABI 위의 서로 다른
  에뮬레이터 설치 계약입니다.
- `host-sim`은 C 표준 라이브러리와 소유권 의미를 빠르게 검사하기 위한
  호스트 프로필입니다. 호스트 포인터 크기나 구조체 배치는 기기 근거가
  아닙니다.

## 메모리와 호출 규약

`MC_knlAlloc`과 `MC_knlCalloc`은 안정적인 C 포인터가 아니라 메모리 ID를
반환합니다. 애플리케이션은 ID를 보관하고 사용할 때마다 `MC_GETDPTR`로
포인터를 해석해야 합니다. 공급자 메모리 압축 뒤에는 전에 얻은 포인터가
무효가 될 수 있습니다.

또한 공개 C 프로토타입과 공급자 호출 규약이 항상 같지는 않습니다. 대표적인
`MC_knlSetTimer`는 64비트 인자 정렬 차이 때문에 검증된 레지스터 재배치
베니어가 필요합니다. 가변 인자 함수나 검증되지 않은 슬롯은 성공한 것처럼
처리하지 않고 명시적으로 링크 또는 실행 실패를 냅니다.

더 자세한 영문 근거는 [아키텍처 문서](../architecture.md)와
[소유권 문서](../ownership.md)를 참고하십시오.
